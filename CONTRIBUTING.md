# Contributing

Thanks for looking. PartSmith is a small project, so issues and focused pull requests work best.

## Set up

You need Python 3.12 with [uv](https://docs.astral.sh/uv/), Node 22 and pnpm.

```bash
make setup    # Python and web dependencies, generated types
make dev      # API on :8000, web on :3000; with no keys every model stage is a labelled mock
```

Copy `.env.example` to `.env` only if you want live model calls. Secrets stay in `.env`, which git ignores.

## The rules the code depends on

1. **Model proposes, code decides.** Model output never sets `verified`. Numbers come from `services/verifier`.
2. **Millimetres everywhere.** Suffix variables `_mm` and angles `_deg`.
3. **Every number shown to people comes from a script.** No hand-typed metrics in the README, the site or the film.
4. **No fabricated results.** If something is untested, say so. Label replays, mocks, synthetic photos and AI images.
5. **LLM-written CAD runs only in the sandboxed worker** (AST allowlist, rlimits, no network).
6. **All model calls go through `services/agent/providers`** and emit a `model_call` event with tokens, time and cost.

## Before you open a pull request

```bash
make test && make lint && make typecheck
pnpm -C apps/web typecheck && pnpm -C apps/web lint && pnpm -C apps/web test
make gitleaks
```

Add or update tests. If you change a stage, emit its events. If you make an architectural choice, add a paragraph to
[docs/DECISIONS.md](docs/DECISIONS.md). If your change affects a number, regenerate with `make bench` rather than editing the
README: its blocks between `BEGIN` and `END` markers are generated by `tools/readme.py`.

## Requesting a part

Use the *Broken part request* issue template, or add it on `/requests` on the site. Medical, vehicle-safety and weapon parts
are refused.
